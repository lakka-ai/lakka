theme, loads nothing from a third party, and passes `pnpm site:check`.
The Pages workflow deploys it to https://lakka-ai.github.io/lakka/, and README.md links it.

Gate (docs/roadmap.md): the five exit criteria below. The work is ADR 0119; the patch to
VitePress's search dialog is ADR 0120.

## What the checks hold the site to

The site's checks were written against what VitePress does by default on phones, tablets and the
keyboard, and each holds the site to the app's rules: code blocks that fit and line up on a phone,
copy buttons shown on touch screens, 44px touch targets below 1024px, the current page marked by
fill and weight rather than colour alone, a closed drawer out of the tab order, focus given back to
the search button when search closes, no focus ring on a heading or content that focus is moved to,
and VitePress's search dialog with valid roles, through a patch (ADR 0120). Two are checked by hand
only: where code starts on a phone, and the weight of code in a heading.

## Departures from the brief

- **`ignoreDeadLinks: 'localhostLinks'`** rather than `false`: the guide links
  `http://localhost:8080`, the reader's own install. Every other dead link fails the build.
- **A pnpm override and a Vue alias**, neither in the brief, both recorded in ADR 0119: one keeps
  Vue out of the product image, the other lets pages in `docs/` resolve Vue without a copy step.
- **`pnpm dev` leaves the site out**, since its filter `./apps/*` would otherwise start it.
- **The guide's placeholders** such as `<name>` are written `\<name>`. GitHub was dropping them
  too.
- **The landing page** is the hero and the four features only, at the owner's request, and fits a
  screen: no Run it, which Install covers, and no What it is not, which the guide's index already
  said. The guide's index is renamed What is Lakka? and listed under a new Introduction section
  above the guide. The nav and the hero each have one link, Docs, to the guide's index, where the
  brief had Guide and Install in the nav and Read the guide and Install in the hero.

## Known gaps

- **The first search on iOS** after a page load opens without the keyboard; the reader taps the
  field. VitePress loads the dialog's code on that first tap and focuses the field once it has
  loaded, and iOS raises the keyboard only for a field focused during the tap. Later searches on
  the page raise it. Fixing it means loading the dialog's code before the first tap.
- **VitePress 2 is an alpha**, pinned exactly; an upgrade is a reviewed change (ADR 0119), and
  rebuilds the search patch until VitePress fixes the roles itself (ADR 0120). The fix is not yet
  offered upstream.
