# M7 gate: observability and release hardening

Status: passed. All 21 acceptance criteria are covered by automated tests, and the
clean-machine runs (ADR 0075 H8) passed on a clean Ubuntu 24.04 host (amd64) and a clean Apple
Silicon Mac, following only `docs/guide/` (Record, below). The Ubuntu run's part B ran every job
natively on amd64, and every job passes on amd64 and arm64 in GitHub Actions. On a repository's
first commit the `upgrade` job has no earlier version and passes without upgrading (ADR 0086);

for the first release tag, `v1.0.0-beta.1`, and passed, and `docs/releasing.md` says how to
verify that release.

Gate (docs/roadmap.md): "every acceptance criterion in the Requirements tab passes on a clean
machine, run by someone following only the published documentation."

## The clean-machine runs (ADR 0075 H8)

The person running these follows only `docs/guide/`, and notes every place where the guide was
wrong, unclear or missing something. **Those notes are the point of the run**, as much as the
checks: documentation is the gate.

Before the first release, install with the guide's "Or from source" path. With a release, use
the release bundle and its verification.

### Part A: as a customer, following the guide

On each machine: a fresh **Ubuntu 24.04 host** (amd64), with nothing but Docker Engine and the
Compose plugin installed from Docker's own instructions, and a fresh **Apple Silicon Mac**, with
nothing but Docker Desktop.

1. **Install** (`install.md`). Time it from the first `docker compose up` to the first model
   answer in chat (NF-D2: under 10 minutes, reading included).
2. **AC 1.** The first-run screen appears, and
   `docker compose logs api worker web | grep -E '"level":"(error|fatal)"'` prints nothing.
3. **AC 3.** `docker compose down`, then time `docker compose up -d --wait` until the page loads:
   under 30 seconds.
4. **Administration** (`administration.md`):
   - invite a second person by link, and have them join;
   - both create an API key;
   - set the second person a member cap of $0.01, and see chat and the API both refuse with
     the budget message (AC 4, AC 10: `budget_exceeded`, 402).
5. **The API** (`api.md`). The curl example answers with the admin's key; `GET /v1/models`
   lists `auto` (AC 15, by hand).
6. **AC 6.** Suspend the second person under **People**: their open chat ends within seconds,
   and their key's next request gets 401.
7. **AC 13.** Turn **Choose models automatically** off: chat and the API still answer, from the
   default model.
8. **AC 17.** `docker compose exec -T api lakka diagnostics > d.tar.gz` and unpack it: the
   provider key does not appear in it (`grep -r` for its first characters).
9. **Backup and restore** (`backup-and-restore.md`): back up, restore, and sign in again.
10. **Health** (`operations.md`): `/healthz` answers `ok`.

### Part B: the automated suite, on the same machine

With the development tools from the README (Node 24 and pnpm), clone the repository at the
gate's commit and run `pnpm ci:local`. It runs every acceptance test above on that machine's
architecture. On the Ubuntu host that covers amd64.
