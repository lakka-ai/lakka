# M8 gate: closing what v1 left open

Status: passed. Every M8 item is built, with its ADR, its requirement's Status reads
`built`, and the tests named by its requirement ID pass, the failure-injection tests included.
Every job passes on amd64 and arm64 in GitHub Actions; on amd64 the sandbox needs the runner's
1 GiB data limit (ADR 0118).

Gate (docs/roadmap.md): "each item has its ADR, its requirement's Status reads `built`, and the
tests named by its requirement ID pass, including the failure-injection tests for rotation, the
rate limit and the sandbox."

The checks run in the CI jobs `check`, `integration` on Postgres 16 and 18, `image`,
`out-of-process`, `upgrade` and `stack`. The "Where it runs" column names the CI job that carries
each check.

## Known gaps

- **Rootless Docker and userns-remap** are untested with the sandbox. Its per-operation users
  (61000 to 61063) must fall inside the mapped range; if they do not, the sandbox never turns
  healthy and the troubleshooting guide says what to do.
- **The e2e suite does not cover the candidates dialog**, and the dialog has no mockup; its logic
  is unit tested and screens.md describes it.
- **A release that bundles a model an admin added as a custom model** takes over its price
  silently. Fixing it changes ADR 0037's ordering or needs new UI; ADR 0116 records it.
- **The trace page shows no step for the rate limit check.** A refused request still shows its
  reason.
- **Better Auth's own encryption** of OAuth access and refresh tokens, with the auth secret, is
  not covered by key rotation (ADR 0115).
- **Cold start** is 15.2 to 15.4 s with the two sandbox services, against 12.5 to 13.1 s without
  them; the limit is 30 s.
